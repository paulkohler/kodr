# Postgres Documents API Trial

This directory is a Kodr example workspace for a larger backend service trial.
The app code should be generated by Kodr against the local model, not by hand.

## Goal

Generate an Express.js API backed by Postgres for a small team documents
service. Postgres should run through Docker Compose, while the Express API runs
locally with Node.js.

## Expected Shape

- Node.js 24 ESM
- Express.js
- `pg`
- native `node:test`
- Docker Compose for Postgres
- SQL migrations
- no UI
- no ORM

## Domain

The API should cover:

- users
- user settings
- documents
- document versions
- document tags
- document sharing or audit events if the model can fit them cleanly

## Provenance

The implementation must come from a Kodr run. If generation fails, record the
failure and diagnose whether Kodr needs a harness improvement before hand-editing
anything in this example.

## Setup

### Prerequisites

- Node.js 24+
- Docker and Docker Compose
- PostgreSQL (or use the Docker Compose service)

### Quick Start

1. **Clone and install dependencies:**

   ```bash
   npm install
   ```

2. **Start PostgreSQL with Docker Compose:**

   ```bash
   docker compose up -d
   ```

3. **Copy environment file and run migrations:**

   ```bash
   cp .env.example .env
   npm run migrate
   ```

4. **Start the API server:**

   ```bash
   npm start
   ```

The API will be available at `http://localhost:3000`.

## Running Tests

Tests require a running PostgreSQL instance. Make sure Docker Compose is running
with the `postgres` service before running tests.

```bash
npm test
```

## API Endpoints

### Health

- `GET /health` — Health check with database connectivity

### Users

- `POST /users` — Create a new user
- `GET /users/:id` — Get a user by ID
- `PATCH /users/:id/settings` — Update user settings

### Documents

- `POST /documents` — Create a new document
- `GET /documents` — List documents (supports `owner_id`, `status`, `tag`, `limit`, `offset` query params)
- `GET /documents/:id` — Get a document by ID
- `PATCH /documents/:id` — Update a document
- `DELETE /documents/:id` — Delete a document

### Document Versions

- `POST /documents/:id/versions` — Create a new version of a document
- `GET /documents/:id/versions` — Get all versions of a document

### Document Tags

- `POST /documents/:id/tags` — Add a tag to a document
- `DELETE /documents/:id/tags/:tag` — Remove a tag from a document

## Schema

The database uses the following tables:

- `users` — User accounts
- `user_settings` — Per-user settings (theme, notifications)
- `documents` — Document records with owner, title, body, and status
- `document_versions` — Version history for documents
- `document_tags` — Many-to-many tags for documents
- `audit_events` — Audit trail for actions
